# Tanyl publication plan

Goal: preserve the supplied curriculum analytics and publish a usable hackathon MVP and GitHub repository.
Architecture: Python analytics shared between local Flask and a browser Pyodide worker. GitHub Pages serves static assets; uploaded CSV stays in browser memory. No backend account or paid infrastructure required.
Decision: user delegated platform selection. Retain Flask for local use. Browser runtime download is the main tradeoff compared with a hosted Python server.

- [ ] Run supplied tests; add regressions for sparse JSON, invalid/infeasible hour plans and export.
- [ ] Correct reproduced defects in shared analytics; preserve budget and explicit integer bounds.
- [ ] Add tested browser bridge for CSV/report/Excel and a worker transport; generate static site from existing UI.
- [ ] Verify tabs, CSV, controls and download in browser; state synthetic-data and observational limitations.
- [ ] Publish public repository and GitHub Pages; verify CI and public URL.

Review focus: single-observation datasets, impossible minimum hours, missing curriculum topics, repeated topic names, CDN/runtime loading errors.
Submission: form requires PDF presentation (under 10 MB), GitHub URL, team institution, leader contacts and member names. User fills team details; no form submission is authorized.
