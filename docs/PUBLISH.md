## 0. Что такое Git, GitHub и Gitea

- **Git**: программа на вашем компьютере. Она запоминает версии файлов проекта (как «сохранения» в игре) и умеет отправлять их на сервер.
- **GitHub**: сайт-сервер, где хранятся такие проекты. Бесплатный, самый популярный. Именно туда вы загрузите код.
- **Gitea**: то же самое, что GitHub, но устанавливается на собственный сервер организации. Если организаторы хакатона дали вам адрес своего Gitea, используйте [вариант B](#вариант-b-gitea-вместо-github). Если нет, берите GitHub.
- **Репозиторий** («репо»): папка проекта вместе с историей изменений, хранящаяся на сервере.
- **Терминал** (командная строка): окно, куда вы вводите текстовые команды. Страшного в нём ничего нет: вы будете копировать готовые команды.

Схема того, что мы сделаем:

```
Папка на вашем компьютере  ──git push──▶  Репозиторий на GitHub  ──▶  Ссылка для жюри
```

## Шаг 1. Установите Git

### Windows
1. Откройте https://git-scm.com/download/win. Скачивание начнётся само (если нет, нажмите «Click here to download»).
2. Запустите скачанный файл `Git-…-64-bit.exe`.
3. Во всех окнах установщика нажимайте **Next**, настройки по умолчанию подходят. В конце нажмите **Install**, потом **Finish**.
4. После установки в меню «Пуск» появится **Git Bash**. Это терминал, в котором будем работать.

### macOS
1. Откройте программу **Терминал** (Cmd + Пробел, введите «Терминал», Enter).
2. Введите команду и нажмите Enter:
   ```bash
   git --version
   ```
3. Если Git не установлен, macOS предложит установить «Command Line Developer Tools». Нажмите **Установить** и дождитесь окончания. Потом снова введите `git --version`.

### Linux (Ubuntu / Debian)
```bash
sudo apt update && sudo apt install git -y
```

### Проверка установки
В терминале (Git Bash на Windows) введите:
```bash
git --version
```
Должно появиться что-то вроде `git version 2.45.1`. Номер может быть другим, это нормально. Если пишет «command not found» или «не является внутренней командой», закройте терминал, откройте заново, а если не помогло, переустановите Git.

> **Как вводить команды:** выделите команду из блока кода, скопируйте (Ctrl+C), вставьте в терминал (в Git Bash это **Shift+Insert** или правая кнопка мыши → Paste; на Mac Cmd+V) и нажмите **Enter**. Строки, начинающиеся с `#`, это комментарии, их вводить не нужно.

## Шаг 2. Зарегистрируйтесь на GitHub

1. Откройте https://github.com/signup.
2. Введите email, придумайте пароль, придумайте **имя пользователя** (логин).
   Логин станет частью ссылки на ваш репозиторий (`github.com/ЛОГИН/...`), поэтому выбирайте нормальное, без случайных символов.
3. Пройдите проверку «я не робот» и подтвердите email кодом из письма.
4. Если уже есть аккаунт, просто войдите.

Запишите свой **логин**, он понадобится в командах дальше. Ниже он обозначен как `ВАШ_ЛОГИН`.

## Шаг 3. Распакуйте проект и откройте терминал в его папке

### 3.1 Распаковка
1. Найдите скачанный архив `data-driven-curriculum.zip`.
2. Распакуйте его:
   - **Windows:** правая кнопка → «Извлечь всё…» → «Извлечь».
   - **macOS:** двойной клик по архиву.
3. Должна получиться папка `data-driven-curriculum`, внутри которой лежат `app`, `tests`, `README.md`, `run.py` и другие файлы.
   Убедитесь, что вы открываете именно ту папку, где **прямо внутри** видны `README.md` и `app`. Бывает, что при распаковке получается папка внутри такой же папки.

### 3.2 Открытие терминала в этой папке

**Windows (самый простой способ):**
1. Откройте папку `data-driven-curriculum` в Проводнике (чтобы были видны `README.md`, `app`).
2. Щёлкните правой кнопкой мыши по **пустому месту** внутри папки.
3. Выберите **«Open Git Bash here»**. В Windows 11 сначала нужно нажать «Показать дополнительные параметры».

**macOS:**
1. Откройте Терминал.
2. Введите `cd ` (с пробелом после `cd`), перетащите папку `data-driven-curriculum` из Finder в окно Терминала (путь подставится сам) и нажмите Enter.

**Если не получилось, универсальный способ** (подставьте свой путь; кавычки обязательны, если в пути есть пробелы или русские буквы):
```bash
cd "C:/Users/Имя/Downloads/data-driven-curriculum"      # Windows (Git Bash): слэши прямые
cd ~/Downloads/data-driven-curriculum                    # macOS / Linux
```

### 3.3 Проверка, что вы в нужной папке
```bash
ls
```
В ответ должен быть список: `Dockerfile  LICENSE  README.md  app  data  docs  requirements.txt  run.py  tests`.
Если вместо этого пусто или другие файлы, вы не в той папке. Вернитесь к 3.2.

## Шаг 4. Представьтесь Git

Git подписывает каждое сохранение вашим именем и почтой. Это делается один раз на компьютере.

```bash
git config --global user.name "Ваше Имя"
git config --global user.email "ваша_почта@example.com"
```

- Имя можно писать латиницей или кириллицей, оно видно всем на странице репозитория.
- Почту лучше использовать ту же, что при регистрации на GitHub. Если не хотите показывать настоящий адрес, в GitHub есть скрытый вариант вида `12345+логин@users.noreply.github.com` (Settings → Emails).

Проверка:
```bash
git config --global --list
```
В списке должны быть ваши `user.name` и `user.email`.

## Шаг 5. Создайте пустой репозиторий на GitHub

1. Откройте https://github.com/new (или нажмите **+** в правом верхнем углу → **New repository**).
2. Заполните форму:
   | Поле | Что ввести |
   |---|---|
   | **Owner** | оставьте свой логин |
   | **Repository name** | `data-driven-curriculum` |
   | **Description** | `Интеллектуальная система оценки эффективности учебников и учебных программ` (по желанию) |
   | **Public / Private** | **Public**: жюри должно видеть код без приглашений |
   | **Add a README file** | **НЕ отмечать** |
   | **Add .gitignore** | **НЕ выбирать** (None) |
   | **Choose a license** | **НЕ выбирать** (None) |
   Три последних пункта пустыми нужно оставить потому, что эти файлы уже есть в проекте. Если создать их на сайте, при загрузке возникнет конфликт.
3. Нажмите зелёную кнопку **Create repository**.
4. Откроется страница с подсказками «Quick setup». Найдите там **адрес репозитория** (строка начинается с `https://github.com/…` и заканчивается `.git`) и скопируйте. Он выглядит так:
   ```
   https://github.com/ВАШ_ЛОГИН/data-driven-curriculum.git
   ```
   Убедитесь, что выбрана вкладка **HTTPS**, а не SSH.

## Шаг 6. Создайте токен доступа (вместо пароля)

С 2021 года GitHub **не принимает обычный пароль** при `git push`. Вместо него используется **токен**: длинная строка-пропуск. Создаётся за минуту.

1. Откройте https://github.com/settings/tokens (или: ваша аватарка справа вверху → **Settings** → в самом низу левого меню **Developer settings** → **Personal access tokens** → **Tokens (classic)**).
2. Нажмите **Generate new token** → выберите **Generate new token (classic)**. Возможно, GitHub попросит ввести пароль.
3. Заполните:
   - **Note:** `hackathon` (любое название, чтобы вы сами помнили, зачем он)
   - **Expiration:** `30 days` (после хакатона токен сам перестанет работать)
   - **Select scopes:** поставьте галочку **repo** (подпункты отметятся сами). Больше ничего не нужно.
4. Прокрутите вниз и нажмите **Generate token**.
5. Появится строка вида `ghp_xxxxxxxxxxxxxxxxxxxxxxxx`. **Скопируйте её сразу** и сохраните в блокнот. GitHub показывает токен **только один раз**; если потеряете, создайте новый.

> **Безопасность:** токен равен паролю от ваших репозиториев. Не отправляйте его другим людям, не вставляйте в чаты и не добавляйте в файлы проекта.

## Шаг 7. Загрузите проект командами Git

Работаем в терминале, открытом в папке проекта (см. шаг 3). Выполняйте команды **по одной**, дожидаясь завершения каждой.

### 7.1 Создайте локальный репозиторий
```bash
git init -b main
```
Ответ: `Initialized empty Git repository in …/data-driven-curriculum/.git/`.
Это значит, что Git начал следить за папкой. Появилась скрытая папка `.git`, трогать её не нужно.

> Если появилась ошибка `unknown switch 'b'`, у вас старая версия Git. Выполните вместо этого две команды:
> ```bash
> git init
> git branch -M main
> ```

### 7.2 Добавьте все файлы в «корзину» будущего сохранения
```bash
git add .
```
Точка в конце обязательна, она означает «всё в этой папке». Ответа не будет, это нормально. Файлы, перечисленные в `.gitignore` (кэш, виртуальное окружение), Git пропустит сам.

Можно проверить, что попадёт в сохранение:
```bash
git status
```
Зелёным будут перечислены файлы (`app/analysis.py`, `README.md` и другие). Всего их должно быть **около 18**.

### 7.3 Сделайте «сохранение» (коммит)
```bash
git commit -m "Initial commit: Data-Driven Curriculum platform"
```
Ответ: `[main (root-commit) abc1234] Initial commit…` и список созданных файлов.
**Коммит** это зафиксированная версия проекта с подписью (то, что в кавычках после `-m`).

> Если выдаёт `Author identity unknown`, вы пропустили шаг 4. Выполните его и повторите коммит.

### 7.4 Привяжите папку к репозиторию на GitHub
```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/data-driven-curriculum.git
```
Подставьте **свой** адрес, скопированный на шаге 5. `origin` это просто имя для адреса («источник»). Ответа не будет.

Проверка:
```bash
git remote -v
```
Должны появиться две строки с вашим адресом (`fetch` и `push`).

### 7.5 Отправьте код на GitHub
```bash
git push -u origin main
```
Git попросит авторизоваться. Что происходит дальше, зависит от системы:

**Вариант 1. В терминале появляются вопросы:**
```
Username for 'https://github.com':
Password for 'https://ВАШ_ЛОГИН@github.com':
```
- На `Username` введите свой **логин** GitHub и нажмите Enter.
- На `Password` вставьте **токен** из шага 6 (не пароль от аккаунта!) и нажмите Enter.
  При вставке **ничего не отображается**: ни букв, ни звёздочек. Так и должно быть, просто вставьте и нажмите Enter.

**Вариант 2. Открылось окно браузера или окно «Git Credential Manager»** (так бывает в Windows):
нажмите **Sign in with your browser** (или «Token») и подтвердите вход на GitHub. Если окно просит токен, вставьте токен из шага 6.

**Успешный результат выглядит так:**
```
Enumerating objects: 30, done.
Counting objects: 100% (30/30), done.
Writing objects: 100% (30/30), 95.40 KiB | 3.18 MiB/s, done.
To https://github.com/ВАШ_ЛОГИН/data-driven-curriculum.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```
Последняя строка `main -> main` означает, что код загружен.

## Шаг 8. Проверьте результат

1. Откройте в браузере `https://github.com/ВАШ_ЛОГИН/data-driven-curriculum` (или обновите страницу, если она открыта, F5).
2. Вы должны увидеть:
   - список папок `app`, `data`, `docs`, `tests` и файлов `README.md`, `run.py`, `requirements.txt` и других;
   - ниже отображается содержимое `README.md` с описанием проекта.
3. Откройте вкладку **Actions**. GitHub автоматически запустил проверку (файл `.github/workflows/ci.yml`) и прогоняет тесты. Через 1–2 минуты появится зелёная галочка ✅. Красный крестик ❌ означает, что тесты не прошли: нажмите на запись, там показана причина.
4. Откройте ссылку **в режиме инкогнито** (Ctrl+Shift+N). Если страница открывается без входа в аккаунт, репозиторий действительно публичный и жюри его увидит.

**Репозиторий опубликован.** Эта ссылка и есть то, что нужно указать в заявке.

### Рекомендуется: оформить репозиторий для жюри
1. На главной странице репозитория справа найдите блок **About** и нажмите на ⚙ (шестерёнку).
2. В **Description** впишите краткое описание, в **Topics** добавьте теги: `edtech`, `python`, `flask`, `data-analysis`, `education`. Нажмите **Save changes**.
3. Запустите проект у себя (`pip install -r requirements.txt`, затем `python run.py`, откройте http://localhost:8000), сделайте **скриншоты** дашборда и положите их в папку `docs/` проекта. Затем добавьте их в `README.md` строкой `![Дашборд](docs/screenshot.png)` и загрузите изменения (см. [раздел про обновление](#как-обновлять-репозиторий-позже)).

## Вариант B: Gitea вместо GitHub

Используйте, если организаторы или ваша организация дали вам адрес сервера Gitea (например `https://git.example.kz`). Шаги 1, 3, 4 те же самые. Различается только создание репозитория и авторизация.

### B.1 Регистрация
Откройте адрес сервера → **Register** (или **Sign In**, если аккаунт уже выдали). Возможно, регистрацию должен подтвердить администратор.

### B.2 Создание репозитория
1. Нажмите **+** в правом верхнем углу → **New Repository**.
2. **Repository Name:** `data-driven-curriculum`.
3. **Visibility:** следуйте требованиям организаторов (если не сказано иное, оставьте публичным).
4. **Не** включайте создание README, `.gitignore` и License: они уже есть в проекте. Если при создании есть переключатель «Initialize Repository», выключите его.
5. Нажмите **Create Repository** и скопируйте HTTPS-адрес со страницы (вида `https://git.example.kz/ВАШ_ЛОГИН/data-driven-curriculum.git`).

### B.3 Токен (если сервер не принимает пароль или включена двухфакторная защита)
1. Аватарка → **Settings** → **Applications**.
2. В блоке **Generate New Token** введите название (`hackathon`), выберите права **repository: Read and Write**.
3. Нажмите **Generate Token** и сразу скопируйте токен: он показывается один раз.

### B.4 Загрузка
Команды те же, что в шаге 7, но с адресом вашего Gitea:
```bash
git init -b main
git add .
git commit -m "Initial commit: Data-Driven Curriculum platform"
git remote add origin https://git.example.kz/ВАШ_ЛОГИН/data-driven-curriculum.git
git push -u origin main
```
На запрос `Username` вводите логин, на `Password` пароль от Gitea (или токен, если вы его создали).

### B.5 Папка `.github`
Папка `.github/workflows` относится только к GitHub. Если Gitea Actions у вас не настроен, она просто будет лежать без дела и не мешает. Если хотите убрать:
```bash
git rm -r .github
git commit -m "Remove GitHub Actions config"
git push
```

## Как обновлять репозиторий позже

Любое изменение (правка кода, скриншоты, текст README) загружается тремя командами:

```bash
git add .
git commit -m "Коротко, что изменили"
git push
```

Правила хорошего тона:
- Делайте **несколько осмысленных коммитов** с понятными подписями (`Add screenshots`, `Fix hours rounding`), а не один гигантский. По истории коммитов жюри видит, что команда работала постепенно.
- Перед коммитом смотрите `git status`: он показывает, какие файлы изменены.

## Типичные ошибки и что с ними делать

| Что видите | Причина | Что делать |
|---|---|---|
| `git: command not found` / «не является внутренней командой» | Git не установлен или терминал открыт до установки | Установите Git (шаг 1), **закройте и заново откройте** терминал |
| `fatal: not a git repository` | Вы не в папке проекта или не выполнили `git init` | Перейдите в папку проекта (шаг 3), выполните `git init -b main` |
| `Author identity unknown` / `Please tell me who you are` | Не выполнен шаг 4 | Выполните две команды `git config --global …` и повторите `git commit` |
| `error: src refspec main does not match any` | Нет ни одного коммита (или ветка называется иначе) | Выполните `git add .` и `git commit -m "Initial commit"`, затем `git branch -M main` и снова `git push -u origin main` |
| `error: remote origin already exists` | Адрес уже был добавлен | Исправьте адрес: `git remote set-url origin НОВЫЙ_АДРЕС` |
| `remote: Support for password authentication was removed` / `Authentication failed` | Вместо токена введён обычный пароль, токен неверный или у него нет галочки `repo` | Создайте новый токен (шаг 6) с правом **repo** и вставьте его на запрос Password |
| `remote: Repository not found` / `fatal: repository '…' not found` | Опечатка в адресе или логине, репозиторий не создан | Сверьте адрес с тем, что на странице репозитория: `git remote -v`, при ошибке `git remote set-url origin …` |
| `! [rejected] main -> main (fetch first)` | В репозитории на сайте уже есть файлы (например, README, созданный на сайте) | Выполните `git pull --rebase origin main`, затем `git push`. Если при этом появились «конфликты» в README, проще удалить пустой репозиторий на сайте и создать заново без галочек (шаг 5) |
| `fatal: detected dubious ownership in repository` | Папка принадлежит другому пользователю ОС (бывает на Windows с флешки или из чужой папки) | Выполните `git config --global --add safe.directory "*"` и повторите команду |
| Вставленный пароль «не вставляется» | Терминал намеренно не показывает ввод пароля | Вставьте токен и просто нажмите Enter |
| Токен вставился с лишним пробелом или переносом | Скопировали лишнее | Скопируйте токен заново, без пробелов в начале и конце |
| На сайте нет папки `app` или файлов внутри лежит ещё одна папка `data-driven-curriculum` | Команды выполнены на уровень выше нужной папки | Удалите репозиторий (Settings → внизу «Delete this repository»), перейдите в **правильную** папку (шаг 3.3), повторите шаги 5–7 |
| Во вкладке Actions красный крестик | Тесты не прошли или не хватило зависимостей | Откройте запись → прочтите сообщение. Локально `python -m pytest -q` должен проходить. Для хакатона ошибка CI не критична, но лучше исправить |

## Мини-словарь

| Термин | Простыми словами |
|---|---|
| **Репозиторий** | Папка проекта с историей всех изменений |
| **Коммит** (commit) | Одно сохранение версии проекта с подписью |
| **Ветка** (branch) | Линия истории; основная называется `main` |
| **Remote / origin** | Адрес репозитория на сервере (GitHub/Gitea) |
| **Push** | Отправить свои коммиты на сервер |
| **Pull** | Скачать с сервера чужие или новые изменения |
| **Токен** | Длинная строка-пропуск, заменяющая пароль при `git push` |
| **HTTPS** | Способ подключения по обычному адресу `https://…`; проще SSH для новичка |
| **`.gitignore`** | Список файлов, которые Git не должен загружать (кэш, окружение) |
| **CI / Actions** | Автоматический запуск тестов на сервере после каждой загрузки |
